# dsh-longmemory 质量基线开发计划

## 目标

在不改变长期记忆业务行为的前提下，完成四项工程治理：文档一致性、依赖环境固化、召回质量评测、性能基准与发布门禁。真实 DSH 宿主端到端验收由用户执行，本轮提供验收说明、数据记录格式和自动检查入口。

## 模块与完成条件

1. **文档一致性**
   - `VERSION` 成为当前版本事实源。
   - Python、JavaScript、发布清单和当前文档均通过自动一致性检查。
   - 工具清单以源码注册表为准，不再手工维护“五把/七把”两套说法。
2. **依赖环境**
   - 固定 Python 3.12 验证基线、核心依赖和可选向量/ANN 依赖。
   - 提供标准库实现的环境预检，输出 `PASS`、`DEGRADED` 或 `FAIL`。
3. **召回质量评测**
   - JSONL 用例包含查询、期望条目、分类和无答案标记。
   - 计算 Recall@5、MRR@5、nDCG@5、无答案误召回率、过期泄漏和重复率。
   - 小型固定样例可在本地与 CI 重复执行。
4. **性能基准**
   - 生成隔离的临时记忆库，不修改真实数据库。
   - 分别测量搜索、读取、时间回放的 P50/P95/P99。
   - 支持门槛检查和相对基线比较。
5. **发布门禁**
   - 串联一致性、预检、单元测试、质量评测、性能基准和构建检查。
   - 所有命令返回可供 CI 使用的退出码。

## 实施顺序

文档与版本事实源 → 环境预检 → 一致性检查 → 质量评测 → 性能基准 → 发布门禁 → 全量回归 → 文档同步 → Git 提交。

## 不在本轮自动执行的内容

- 真实 DSH UI 安装、点击与截图。
- 真实宿主的 `ctx.llm`、`ctx.tools`、`deriveMessages()` 和第三方插件交错验证。
- 使用生产记忆库执行压力测试。

以上项目由用户按 `docs/real_dsh_acceptance.md` 执行，结果写入 `test/docs/`。
