# 项目架构

## 目录职责

| 路径 | 职责 |
|---|---|
| `src/*.py` | 长期记忆 Python 内核 |
| `src/js/` | DSH 宿主外壳与浏览器客户端 |
| `release/` | 可安装插件产物 |
| `scripts/` | 构建、一致性、预检与发布门禁 |
| `tests/` | 单元、契约、模拟端到端、质量和性能测试 |
| `docs/` | 当前设计、运维和验收说明 |
| `test/docs/` | 每次实际测试的证据记录 |

## 变更边界

源码只在 `src/` 修改，`release/lib` 与 `release/kernel` 由构建脚本生成。版本只在 `VERSION` 决策，其他文件必须与其一致。质量与性能工具不得写入生产数据库，默认产物写入 `.tmp/`。

## 发布流程

1. 在 `dev` 分支完成模块开发与测试。
2. 更新相关设计和验收文档。
3. 执行 `scripts/release_gate.py`。
4. 执行真实 DSH 验收并归档截图与日志。
5. 合并发布分支并创建与 `VERSION` 一致的 Git 标签。

## 责任边界

本仓库自动验证源码、发布产物、离线检索质量和本地性能。真实 DSH 宿主安装、UI 操作、第三方插件交错和生产环境数据由人工验收负责。
